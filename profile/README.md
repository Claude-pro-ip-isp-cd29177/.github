<p>做跨境的人大多有一个固定的夜班：晚上八点开工，盯着几个竞品后台看价格、库存和投放变化，一直到凌晨。这段时间里最怕的不是看不过来，而是看到一半连接断了、账号被弹验证，前面积累的页面状态全部作废。这篇按时间线写一遍夜班流程，从交接、上号、跨日、换线到收尾，每一步说明该看什么指标、什么阈值该动手。出口用双 ISP 家宽、一个号一套环境，好处只有在这样的连续时间段里才体现得出来。</p>

<h2>一、19:30 交接：先把今晚要用的出口点名</h2>

<p>夜班开始前十分钟，别急着登录。先对着交接表把今晚要用的每条出口点一遍名：哪条出口配哪个账号、当前出口城市、上一次验证时间、上一位使用者有没有报过异常。点名的作用是把「未知」提前暴露，而不是等到凌晨一点在客户面前才发现某条线不通。</p>

<h3>点名要看的三行数据</h3>
<p>第一行是出口地址与 ASN，确认还是那条家宽运营商，没有被悄悄换成别的段。第二行是连通性，对目标站点发一次轻量请求，看是否在一秒内返回。第三行是账号状态，只看登录页是否能正常加载，不做任何操作。三行都正常才进入下一段。</p>

<h3>发现异常时的处理顺序</h3>
<p>先换备用出口，再记录，再上报。夜班时段不适合做深度排查，能切到备用线路保证作业连续，比在原地分析原因更有价值。记录里写清楚时间、现象、切到了哪条线，白班接手时才有线索可查。</p>

<h2>二、21:00 第一轮上号：最重的活放在开局</h2>

<p>夜间线路状态最好的时段通常在前半夜，尤其是晚八点到十一点。把需要连续翻页、需要保持会话的活放在这一段，比留到凌晨三点做要省事得多。理由很简单：这个时段出口带宽更宽松，站点响应也更快，出错概率低。</p>

<h3>一个号一套环境，别在同一窗口切号</h3>
<p>多号并行时最容易犯的错是在同一个浏览器窗口里退出再登另一个号。缓存、Cookie、本地存储会互相污染，即便出口不同，环境痕迹也串了。正确做法是每个号一个独立实例，各自的用户目录分开存放，出口与实例一一绑定，切换时切换整个实例而不是切换登录状态。</p>

<h3>双 ISP 的意义在这个时段最明显</h3>
<p>双 ISP 出口指的是同一条住宅线路背后有两套运营商归属。它的实际价值不是「更快」，而是在某一家运营商的路由抖动时能换到另一套继续跑。夜班长时间在线，单条线路遇到一次十几分钟的抖动，就足够让一轮抓取白做。所以开工时就把主备两条都验一遍，别等出问题才找备用。</p>

<h2>三、00:00 跨日节点：计费切点与日志归档</h2>

<p>凌晨零点这个时间点，做两件事：一是让日志按日切分，二是核对按量计费的用量。按量计费通常按自然日或按小时结算，跨日前后各截一次用量快照，月底对账时才说得清哪一天的用量异常。日志按日切分的好处是，出现问题能快速定位到某一天某个时段。</p>

<h3>整点检查不要打断正在跑的任务</h3>
<p>如果某个抓取任务正好跨过零点，别在任务中途切出口。会话中途换出口，比一直用同一条略脏的出口更容易触发验证。要么等这一轮跑完再换，要么在任务开始前就换好。</p>

<h2>四、03:00 低峰换线：备用线路真正派上用场的时段</h2>

<p>凌晨三点左右是全天流量最低的时段，也是做线路维护最合适的时间窗。这个点换线，影响面最小，切换失败还有几个小时可以补救。把「计划内换线」放在这里，比白天临时抢修从容得多。</p>

<h3>换线要按固定顺序做</h3>
<p>先在新出口上跑通连通性测试，再登录一个非关键号做一次完整会话，确认没有额外验证，然后把关键号的出口配置切过去，最后回收旧出口。顺序反过来，先切关键号再测，一旦不通就是事故。</p>

<h3>切换后要观察十五分钟</h3>
<p>刚切过去的前十五分钟最容易暴露问题：路由收敛没完成、DNS 缓存没刷新、目标站点对陌生地址更敏感。这十五分钟里保持有人盯着，别切完就去忙别的。</p>

<h2>五、06:30 收尾：把结果留给白班的人</h2>

<p>收尾不是关掉电脑就完事。至少留四样东西：本轮抓取的完整度、缺失页面清单、遇到过的异常与处置、今晚用过的出口列表。白班接手的人拿到这四样，能直接接着干，不用再花半小时重建上下文。</p>

<p>如果夜班是轮值的，再补一句「哪条线建议今晚别用」。这类口头提醒写进记录里更可靠，因为轮值的人会换，记录不会。</p>

<h3>别在收尾时段做大改动</h3>
<p>早上六七点是最疲惫的时候，也是判断力最差的时候。这个时段适合归档，不适合改配置、不适合换服务商、不适合清理环境。所有需要决策的事，留到白天有人复核时再做。</p>

<h2>常见问答</h2>

<h3>夜里掉线了应该先做什么？</h3>
<p>答：先切备用出口把作业续上，再记录现象。夜班时段排查成本高，优先保证任务连续。记录里写清时间、报错原文、切换到的线路，白班再决定是换线还是查环境。</p>

<h3>一个号一套环境具体指什么？</h3>
<p>答：独立的浏览器实例与用户目录、独立的出口地址、独立的时区与语言设置，三者一一绑定。切换账号时切换整个实例，而不是在同一个窗口里退出重登，避免缓存与本地存储互相污染。</p>

<h3>双 ISP 出口真能减少中断吗？</h3>
<p>答：它的作用是提供一套可切换的备用归属，在单条运营商路由抖动时能换过去继续跑，而不是让线路本身变得更快。前提是两条都提前验过，且切换流程固定、切换耗时可控。</p>

<h3>夜班需要一直有人盯着吗？</h3>
<p>答：不需要全程盯，但关键节点要在。开工点名、上号首轮、跨日切点、计划换线的十五分钟内，这四个时段必须有人。其余时间靠监控告警加日志即可。</p>

<h2>合规提示</h2>

<p>访问竞品后台、抓取公开价格与库存信息时，应遵守目标网站的服务条款、robots 协议与当地数据保护法规，只采集公开可获取的信息，不绕过访问控制，不抓取个人隐私数据。</p>

<p>多账号运营需基于真实业务需要，不得用于伪造身份、虚假交易、批量注册或其他违法用途。团队协作应保留操作授权与记录。</p>
